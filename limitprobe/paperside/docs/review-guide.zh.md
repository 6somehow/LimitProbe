# 独立人工审查与汇总

此模块评价候选测试规格与拟议 Oracle 的设计质量。生成器、静态检查器和报告程序均不替人填写评分；没有人工记录时，报告明确显示待审。

## 打开人审包

生成运行的 `results.json` 后，调用 `export_review_pack(run_path, output_dir, seed=0)`。输出包含：

- `reviewer.html`：可直接在本地浏览器打开的匿名审查页面。
- `review-items.json`：打乱顺序的候选、论文和代码证据；不含来源方法与原候选 ID。
- `reviews.csv`：空白评分表；也可以在页面填写后导出 CSV 或 JSON。
- `run-manifest.json`：所有任务，包括失败、弃权与零输出任务。
- `private/blinding-map.json`：实验管理员保存的来源方法映射。审查者不应阅读。

页面显示具体输入、前置条件、目标条件、拟观察行为、证据原文和拟议 Oracle。原文 URL 与绝对本地路径可点击；浏览器若不允许文件链接，按显示的路径在编辑器或 PDF 阅读器中打开。`metadata.paper_references` 应按 paper ID 提供全文与固定版本仓库入口，因此没有论文引文的候选仍能对照全文。

页面只在本地浏览器保存草稿，不上传记录。填写你自己的 `reviewer_id`，切换身份后使用独立草稿，避免继承其他人的评分。完成后导出文件；浏览器存储可能被清理或禁用，不能把自动保存作为唯一备份。再次打开可以导入自己的 JSON。两人应独立完成，提交前不要相互查看评分。

输出结构、引文数量与措辞可能暴露方法，所以这是有局限的匿名审查。代码证据和原文必须保留，不能为了盲审删除评判所需信息。

## 六项评分

每项只填 `yes`、`no`、`unknown`；留空表示尚未审查。`unknown` 是已审查但证据不足，不能用空白替代，也不能被算成失败评分。

| 字段 | 审查问题 |
| --- | --- |
| `scope_relevance` | 对照论文全文，输入和目标机制是否处于可支持的研究范围？缺少论文引文不能自动判 no。 |
| `code_alignment` | 固定 commit 的代码是否支持所述条件与测试意图？有行号或引用字符串不等于语义成立。 |
| `input_concreteness` | 参数、配置或操作序列是否具体，必要前置条件是否清楚？ |
| `strategy_appropriateness` | 静态上该策略是否合理针对条件？这不等于证明实际触达。 |
| `observation_clarity` | 是否明确说明要观察什么，及观察量可从何处获取？这不等于已获得观测。 |
| `oracle_design` | 是否有独立判定关系、适用前提和所需观测？分支变化与输出不同本身不能判 bug。 |

在 `reason` 中记录依据、文件或页码以及未决条件。正常控制和错误规格控制可以帮助冻结 rubric，但不能把修复时使用的控制集当独立结果。前五项共同定义合格候选，Oracle 设计单独统计；不把静态 gate 当语义 Oracle。

## 汇总与分母

调用 `aggregate_reviews(run_path, review_files, output_dir)`，可同时导入多个 CSV / 页面导出的 JSON。默认每项需要至少两名不同审查者。相同 `(review_id, reviewer_id)` 的完全相同记录可重复导入；内容冲突会报错，不会偷偷选最新结果。未知编号、非法评分和已填写但缺少 reviewer ID 的记录也会报错。

- 两人一致 yes / no 才形成该项确认判断；yes 与 no 保留 conflict；unknown 不会自动转换为 no。
- 未审或仅一人审查保持 pending；不会用静态检查填补。
- 任务没有候选时 yield 明确为 0，仍保留在全部任务分母中。
- 有待审或分歧时显示合格数量、任务完成率的下界与上界。这些不是置信区间，也不能据此宣称方法胜出。
- 15、16、17 这种同一测试的多个输入不能算三个研究样本。程序仅自动去掉测试意图字段完全相同的规格，语义重复仍需人工说明。
- 配对差值按相同 task ID 对齐方法；相同 paper 的不同机制不能随意混用。任务、paper 版本、commit 和预算应先冻结。

汇总输出 `evaluation.json`、`evaluation.md` 和可直接打开的 `evaluation.html`。人工记录、分歧、任务级计数与机械检查分开保留。此模块不生成已验证可执行性、动态覆盖、误报率、bug 数或 final paper 的研究结论。

可选真实执行应保存在独立日志中；需要明确选择方式、人工适配成本、真实触达与 semantic result，不能把本模块的静态结果改名为执行验证。
