# Shared schema v0.2.1 (Wanting is responsible; review by all three needed)

Defined in `schema/models.py` (pydantic v2, `extra="forbid"`). Non-Python modules can validate using
`schema/json/*.schema.json` (generated by `python -m schema.export_json_schema`).

## Record types and producers

| Record | Producer | Key fields |
|---|---|---|
| Artifact | All three jointly | repo_url, commit, entry_points, execution_env |
| Claim | Zhaopeng (step 1) | mechanism, statement, kind, evidence |

## Key conventions

- **ID**: unique within each artifact. Suggested prefixes: `C` claim, `S` scope, `E` eval, `B` binding, `R`/`X` region (gold / extracted), `PL`/`CL` paper-side / code-side limitation, `V` verification, `F` finding, `T` test.
- **TextEvidence.quote must appear verbatim in the source** (gate rule, to be checked automatically later).
- **CodeLocation.file is a path relative to the repository root**; line numbers correspond to `Artifact.commit`.
- **Region.condition.expr uses code-level names**; the mapping from paper parameters to code names belongs only in Binding.
- **provenance** distinguishes ast / llm / manual; **confidence** distinguishes mechanical / llm_assisted / llm_only.
- **Outcome**: mechanism, mechanism_variant, fallback, reject, env_dependent, state_dependent, suspicious.
- **FindingCategory (v0.2.1)**, 8 categories:
  | Category | Origin | Meaning |
  |---|---|---|
  | `undisclosed` | Code side | The code has this limitation, but it is not documented anywhere users can read (core finding) |
  | `contradicts_docs` | Code side | Documentation contradicts code behavior |
  | `stated_differently` | Code side | Documented, but with a different boundary or a weaker statement ("only tested on bf16" vs code enforcing bf16) |
  | `docs_only` | Code side | Documented in README / public function docstring, but not in the paper |
  | `paper_stated` | Code side | Documented in the paper with a boundary consistent with the code |
  | `impl_deviates` | Paper side | Described in the paper, but implemented differently in code |
  | `not_implemented` | Paper side | Described in the paper, but absent from code |
  | `paper_hypothesis` | Swarm | Candidate hypothesis with a paper quotation |
- **Unified rule for whether something is documented**: count only places users will read—the paper (including appendices), README, other user documentation, and public function docstrings.
  Code comments (including TODO/FIXME), private function docstrings (names beginning with `_`), and statements containing only a version number do not count.
- **Finding.review**: `unreviewed` / `worth_testing` / `real_but_minor` / `wrong`; `review_note` records who reviewed it
  (`human:<name>` or LLM) and the reason.

## Version history

- **v0.2.1** adds `Finding.origin` (`v1` or `swarm`, defaulting to `v1` for old records),
  `paper_hypothesis` and optional `Limitation.swarm_category`, `Limitation.swarm_provenance`.
  See the [Swarm interface](12_swarm_interface.md) for category mappings and provenance information.
- **v0.2.0** (Wanting's draft, pending agreement by all three): FindingCategory changed from 5 categories to the 7 above
  (`undocumented`→`undisclosed`, `documented_elsewhere`→`docs_only`, `confirmed`→`paper_stated`,
  `paper_only`→`not_implemented`; the former `boundary_mismatch` split into code-side `stated_differently` and paper-side `impl_deviates`;
  3b `contradicted` became a separate `contradicts_docs`); added `Finding.review` and `Finding.review_note`.
  `data/pilot_flexprefill/draft_findings.json` has been migrated to the new names. See `docs/09_step4_findings.md` for the witness_hint format (witness-v2).
- v0.1.0: initial version.
