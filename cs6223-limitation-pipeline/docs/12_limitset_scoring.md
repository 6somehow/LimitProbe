# Reference coverage scoring

Run `conda run -n findlimit python -m scorer_limitset --pred predictions.jsonl --root DATASET --splits data/limitset/splits.json --out OUTPUT`. The default independent judge uses the pipeline relay and the dataset rubric; `--model` and `--temperature` select its recorded configuration. Each request contains only one reference, one finding, heuristic signals and the rubric, never generator logs. `--judge fake` is for offline tests only, not a semantic evaluation.

Each JSONL record is one repeat for its case. Unsubmitted cases have no observations. A finding must be judged as matching the reference mechanism, conditions and consequence. Field coverage comes from the judge for one matched finding, chosen by most covered fields and then input order. Other findings are flagged for human review, not treated as errors. The JSON includes per-repeat decisions and deterministic overlap signals, case stability, and coverage by category and split. Wilson intervals use one observation per case: found if any repeat matches. Repeats share the same case and reference, so they are not independent observations. The mean per-case repeat rate is reported separately. Empty groups have null fractions and intervals.

The dataset's `score_annotations.py` aggregates human annotations and includes metrics outside this task's scope; it does not decide matches or field coverage. This scorer therefore does not reuse its aggregation. The selected references do not establish the validity of novel findings. Judge output is a review, not a verified scientific conclusion.

The CLI validates labels and predictions against the dataset schemas using a minimal checker for their supported keywords. Invalid records appear in case `validation_errors`, or `invalid_records` if no case can be identified. Unreviewed cases have null `found` and are excluded from coverage denominators. Judge connection failures are retried with a timeout; an unavailable judge yields a null match unless another finding matches, and deterministic signals remain available as field results.

`score.json` has `cases` entries with `case_id`, `category`, `split`, `found` (true, false, or null), and `fields`, compatible with the report input. Entries also contain repeats, stability, validation errors and judge availability. `judge` records model ID, prompt version and temperature; `aggregate` contains case-level Wilson intervals and mean per-case repeat rates by category and split. Field results use the best matched repeat, or deterministic signals when the judge is unavailable; they are not proof of semantic coverage.
